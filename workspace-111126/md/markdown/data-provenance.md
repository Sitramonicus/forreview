# What is real and what I made up

Every figure in this system is one of three things: **from the source files**, **calculated** by
the payroll engine from those sources, or **generated by me** because the brief told me to fill in
the gap. Only the third kind is invented, and this page lists all of it.

---

## 1. Real — straight from the supplied files

| Data | Source | Note |
|---|---|---|
| 34 employees (ID, name, birthday, address, phone, SSS/PhilHealth/TIN/Pag-IBIG numbers, status, position, supervisor) | `Copy of MotorPH_Employee Data - Employee Details.csv` | Unchanged. Addresses are used only for branch assignment and never shown in the UI. |
| Basic salary, rice subsidy, phone allowance, clothing allowance, semi-monthly rate, hourly rate | same CSV | **All 34 rows have a real basic salary.** Nothing was assigned. |
| The December 2023 timecard for 10015 | `Copy of MotorPH Sample Timecard - MotorPH Payslip.csv` | 41 rows. Used as the pattern for the generated attendance. |
| The sample payslip figures | same | The golden test reproduces 26,750.00 / 4,500.00 / 8,538.33 / 22,711.67 to the centavo. |
| SSS, PhilHealth, Pag-IBIG, BIR tables | 2026 schedules, effective-dated in `StatutoryRates` | Checked against sweldongpinoy.com on 25 cases. |

## 2. Calculated — the engine's own output

Gross pay, premiums, overtime, night differential, statutory shares, withholding tax and net pay
are **never stored as numbers I typed**. They come out of `CutoffPayrollService` and
`StatutoryCalculator2026` from attendance + salary. If the input is wrong the output is wrong, but
the output is never invented separately.

---

## 3. Generated — the part I made up

The brief (§10) said: *"Populate attendance and payroll records for every employee… Create
coherent attendance records across enough completed payroll periods… Where the employee CSV or
sample timecard does not establish a value, choose a plausible assumption, document it."*

So this exists only because it was asked for.

### Attendance: **10,358 rows**, 34 employees, 2025-09-01 → 2026-11-07

Generated by `tools/seed_attendance.py`, and every row was written through the real
`POST /api/attendance` endpoint, so it passed the same validation a human's entry would.

The assumptions, in full:

- Weekday shift is **08:00–12:00, 13:00–17:00**, taken from the sample timecard.
- Clock-in lands **07:52–08:06**. Clock-out lands **17:00–18:10**.
- **~1 day in 11** is a late arrival (08:15–08:50).
- **~1 day in 23** is an absence — no row at all.
- **Saturday is a rest day**; about 1 in 6 has a 4-hour shift worked on it.
- **Sunday is never worked.**
- No shift crosses midnight, so no two shifts can overlap.
- **Leave was not seeded.** The workflow tests build their own. Inventing approved leave would
  mean inventing approvers who never approved anything.
- **The current month is never written to**, so nothing claims a payroll period that has not
  finished.
- The randomness is seeded (`random.Random(20260101)`), so the same run produces the same rows.

### What was deliberately *not* generated

- **No employee was invented.** All 34 are the CSV's.
- **No salary was invented.** All 34 are the CSV's.
- **No payslip was pre-saved.** They are calculated on request from the attendance above.
- **No approval, leave, overtime or ticket record was invented.** Those have real workflows with
  real approvers, and faking the outcome would misrepresent who did what.
- **No government number was invented.** All came from the CSV.

---

## How to tell the difference at runtime

- The attendance API labels every seeded row `"dayType": "Imported"`. Rows a person enters through
  the UI are labelled the same way because the store does not currently distinguish. **If a row
  came from the seeder, nothing in the UI says so** — that is a real limitation, and the only
  defence is this page.
- The payroll engine reconciles every payslip against its attendance (`"reconciled": true`). A
  payslip that does not reconcile is refused, so no figure can drift from its inputs unnoticed.

---

## If someone asks "is this company's real payroll history?"

No. It is a coherent, internally consistent 14-month attendance history built from the sample
timecard's shift pattern, run through the real calculation rules on the real salaries. It is
suitable for demonstrating and testing the engine. It is not a record of what MotorPH paid anyone.
