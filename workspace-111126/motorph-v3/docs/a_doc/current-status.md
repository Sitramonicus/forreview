# Current status

## Work completed

- Firestore uses server-side Application Default Credentials with refresh rather than an employee-held token. Writes are synchronous atomic commits with a stale-writer precondition; failed/ambiguous writes stop further writes. Manual backup/list/restore and audit archive writes are supported. See [Firestore setup](../firebase-setup-guide.md) for the required pepper, IAM, limits and recovery precautions.
- All accounts use the shared initial password specified for the build. After the code step, sign-in opens the workspace directly; changing a password from My account is optional.
- System configuration → Account access & passwords gives IT controls to activate/deactivate accounts, unlock them, and reset their password to the shared initial password. Deactivation signs the account out and blocks future sign-in; activation restores access.
- Sign-in now opens five distinct role workspaces instead of a generic Overview: Employee self-service, Supervisor team operations, Payroll operations, HR people operations, and a System Administrator control desk. The admin home centers on access posture, system storage and verification, roles/policy, and recent audit activity; its live counts come from admin APIs.
- My Pay has a MotorPH/fixed-rate estimate switch available to employees. It is not a live Sweldong Pinoy result and does not change payroll records. I corrected UI copy that had overstated parity. See [provenance and assumptions](data-provenance.md) and [the captured browserless probe](sweldong-reference-probe.md).
- Added an admin-only storage status and round-trip check. It reports the configured store and aggregate in-process counts; the verifier compares the running state with the configured store, commits the unchanged snapshot through the normal store implementation, reads it back, and fails closed on mismatch. Local controlled-store tests cover success and failure handling. This does not establish live Firestore reliability. See [storage verification](storage-verification.md).
- Added a separate admin-only, optional Sweldong Pinoy reference comparison. It is restricted to 2026 Private Employee / Monthly with the captured 20-day / 5-day defaults and zero night differential/overtime. Every transfer requires explicit consent. It validates the external result, preserves source/version and raw response evidence, renders component deltas, keeps MotorPH as the default, and records an explicit reference-only choice in the audit log. It has no payroll-application path. Tests use a local simulated provider only; no live request or real payroll data was used. See [comparison details](sweldong-reference-probe.md).

## Remaining risks and work

- **Live data:** an earlier non-atomic writer was forcibly stopped; the current state of `motorph-jd` is unknown. Export and inspect it before writing or migrating. Do not overwrite it with the sample seed.
- **Scale and availability:** this is a single-instance full-snapshot architecture with in-memory sessions and an atomic request size limit; it is not a normalized, multi-instance database. Independent backup/export, retention, restore drills, monitoring and load tests are still needed. A timeout can leave a committed write with an uncertain response.
- **Payroll:** generated seed attendance is not actual history; there were 130 future-dated rows relative to 2026-11-02. The temporary 2026 rules and reference assumptions need review by qualified payroll personnel. Sweldong Pinoy's full current implementation has not been verified and the reference is not claimed to reproduce it exactly.
- **Dependencies:** npm reported 30 findings (10 high, 20 moderate); the direct flagged dependency is development tooling. Java dependencies require a separate vulnerability and license inventory. See [risk review](dependency-risk-review.md).
- Earlier audits and session notes are historical snapshots; they may describe defects that have since been fixed or make claims later corrected here. The full original brief, comprehensive security/accessibility review, complete source-comparison provenance, and production deployment acceptance have not all been independently verified.
